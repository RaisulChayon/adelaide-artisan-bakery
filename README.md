# Adelaide Artisan Bakery

A local bakery catalogue and customer enquiry website built with FastAPI, Jinja2, SQLAlchemy and SQLite.

This README is written for running, testing and demonstrating the application locally.

## 1. Technology Stack

| Technology    | Purpose                              |
| ------------- | ------------------------------------ |
| Python 3.12.x | Backend programming language         |
| FastAPI       | Web framework and application routes |
| Uvicorn       | Local ASGI server                    |
| Jinja2        | Server-side HTML templates           |
| SQLAlchemy    | ORM and database access              |
| SQLite        | Local persistent database            |
| HTML5         | Page structure                       |
| CSS3          | Responsive styling                   |
| Pytest        | Automated testing                    |
| HTTPX         | Test client dependency               |
| python-dotenv | Environment configuration            |

## 5. What Should Be Missing From Git

The following should normally NOT be committed:

```text
.venv/
.env
bakery.db
__pycache__/
.pytest_cache/
*.pyc
```

### Why?

`.venv/`

The virtual environment is machine-specific and can be recreated using `python -m venv`.

`.env`

This contains local environment configuration. It is intentionally ignored so that environment-specific values are not committed.

`bakery.db`

This is the local SQLite database generated by the application. A fresh user can create it by running the application and/or `seed.py`.

`__pycache__/` and `*.pyc`

These are Python-generated cache files.

`.pytest_cache/`

This is generated by Pytest.

## 12. Where Is the Database?

The application uses SQLite.

With:

```env
DATABASE_URL=sqlite:///./bakery.db
```

the database file is:

```text
bakery.db
```

in the project root.

The structure will look like:

```text
adelaide-artisan-bakery/
│
├── app/
├── static/
├── templates/
├── tests/
├── bakery.db
├── .env
├── requirements.txt
└── README.md
```

The database is persistent.

For example:

```text
Create product
      ↓
FastAPI
      ↓
SQLAlchemy
      ↓
SQLite
      ↓
bakery.db
```

If the server is stopped and started again, the stored data remains in `bakery.db`.

## 13. How the Database Is Created

The application creates the database tables when it starts.

The SQLAlchemy models are defined in:

```text
app/models.py
```

The database connection is configured in:

```text
app/database.py
```

The application creates the tables through:

```python
Base.metadata.create_all(bind=engine)
```

There is also a `seed.py` script that adds sample bakery products.

## 33. Common Problems

### `python` is not recognised

Try:

```cmd
py --version
```

Then:

```cmd
py -3.12 -m venv .venv
```

### Wrong Python version

Run:

```cmd
py -0p
```

If Python 3.12 is installed:

```cmd
py -3.12 -m venv .venv
```

### `uvicorn` is not recognised

Make sure the virtual environment is activated:

```cmd
.venv\Scripts\activate
```

Then use:

```cmd
python -m uvicorn app.main:app --reload --port 8000
```

### `pip` installs to the wrong Python

Use:

```cmd
python -m pip install -r requirements.txt
```

instead of:

```cmd
pip install -r requirements.txt
```

### Port 8000 is already in use

Use another port:

```cmd
uvicorn app.main:app --reload --port 8001
```

Then open:

```text
http://127.0.0.1:8001
```

### Database does not contain sample products

Run:

```cmd
python seed.py
```

### Changes are not appearing

Make sure the server is running with:

```cmd
--reload
```

and refresh the browser.
